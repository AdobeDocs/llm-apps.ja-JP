# アプリの変数とシークレットの設定 {#app-variables}

>[!IMPORTANT]
>
>[!DNL Adobe LLM Apps]は現在Betaにいます。
>
>ここに示す機能、ワークフロー、UIは、必ずしも製品の最終状態を表すものではありません。 Betaに参加するには、llm-apps-beta@adobe.comに電子メールを送信します。

変数とシークレットを使用して、アクションハンドラーで値をハードコーディングせずにアプリを設定します。 例えば、アプリが呼び出す製品カタログ APIのURLを、ステージングのテストサービスと実稼動環境のライブサービスを使用して、ハンドラーコードを変更せずに設定します。

変数には、機密性のない設定が保持されます。 シークレットは、API キーやアクセストークンなどの機密性の高い値を対象としています。

>[!IMPORTANT]
>
>現在、**変数**&#x200B;のみがサポートされています。 シークレットのサポートは、今後のリリースで予定されています。 それまでは、**パスワード、API キー、アクセストークン、またはその他の機密情報**&#x200B;を変数&#x200B;**に保存しないでください。これらの値は、設定テーブルに表示され、コピー可能です。**

**ジャーニー:** ハンドラーで変数または秘密鍵を追加→、テストをデプロイ→て読み取→ます。

## 始める前に {#before-you-begin}

次のものが必要です。

- **アプリのハンドラーリポジトリ**&#x200B;にアクセスできるので、必要に応じてハンドラーを更新して変数を読み取ることができます。
- そのリポジトリ内の&#x200B;**`@adobe/llm-apps-runtime`1.1.0以降**。 2026年8月以降に作成されたアプリには、既に含まれています。

バージョンを確認するには、ハンドラーリポジトリでこれを実行します。

```bash
npm ls @adobe/llm-apps-runtime
```

バージョンが1.1.0より前の場合は、アップグレードしてから、`package.json`と`package-lock.json`をコミットしてプッシュします。

```bash
npm install @adobe/llm-apps-runtime@latest
```

## 変数の管理 {#manage-variables}

各環境（**[!UICONTROL ステージ]**&#x200B;または&#x200B;**[!UICONTROL 実稼動]**）には独自の変数が設定されているので、**[!UICONTROL Workspace]**&#x200B;を確認してから、その変数を追加、更新、削除してください。 変更は、次回その環境にアプリをデプロイしたときに有効になります。

### 変数の追加 {#add-variable-to-app}

このガイドでは、値`Good day`を持つ`GREETING_PREFIX`という名前の変数を機密性のない例として使用し、ハンドラーのデフォルトの挨拶`Hello`を上書きします。 変数を追加すると、**not**&#x200B;はアクションを自動的に変更しません。ハンドラー&#x200B;**は**&#x200B;を読み取る必要があります。

#### 手順1:UIでの変数の追加 {#add-a-variable}

1. アプリを開き、左側のナビゲーションで「**[!UICONTROL 設定]**」を選択します。
2. 「**[!UICONTROL 変数と秘密鍵]**」タブを開きます。



3. **[!UICONTROL Workspace]**&#x200B;で、**[!UICONTROL ステージ]**&#x200B;または&#x200B;**[!UICONTROL 実稼動]**&#x200B;を選択します。
4. 「**[!UICONTROL 追加]**」を選択します。

   ![変数と秘密鍵 – 「追加」ボタン付きの空のステージワークスペース ](/help/assets/guide-app-variables/variables-empty.png)

5. ダイアログで、次のように入力します。
   - **[!UICONTROL 名前]**: `GREETING_PREFIX`。
   - **[!UICONTROL 種類]**: **[!UICONTROL 変数]**&#x200B;を選択したままにします。
   - **[!UICONTROL 値]**: `Good day`。

   ![変数または秘密鍵を追加 – GREETING_PREFIXが「良い日」に設定](/help/assets/guide-app-variables/add-variable-dialog.png)

6. **[!UICONTROL 追加]**&#x200B;を選択して保存します。

変数は、**[!UICONTROL 名前]**、**[!UICONTROL 種類]**、**[!UICONTROL 値]**、**[!UICONTROL 最終更新日]**&#x200B;のテーブルに表示されます。 値をコピーする必要がある場合は、値の横にあるコピーコントロールを使用します。

![変数と秘密鍵 – ステージワークスペースに保存されたGREETING_PREFIX](/help/assets/guide-app-variables/variable-added.png)



>[!IMPORTANT]
>
>保存すると、選択した環境の設定に変数が追加されます。 再びデプロイするまで、**は** デプロイされたアプリを更新しません。

#### 手順2: ハンドラーで変数を読み取る {#use-a-variable}

ハンドラーリポジトリで、`actions/<action-name>/index.js`を開きます。 ハンドラーが2番目の引数`extra`を受け入れて、`getVariable`を含む変数を読み取ることを確認してください。

```javascript
const { getVariable } = require('@adobe/llm-apps-runtime');

module.exports = async ({ name = 'there' } = {}, extra) => {
  const prefix = getVariable(extra, 'GREETING_PREFIX') || 'Hello';

  return {
    content: [{ type: 'text', text: `${prefix}, ${name}!` }]
  };
};
```

値が`Good day`の場合、`name`が`Ada`に設定された呼び出しは、デフォルトの`Hello, Ada!`ではなく`Good day, Ada!`を返します。 後で値を`Howdy`に変更すると、別のハンドラーの編集なしで、再デプロイ後に挨拶が変更されます。

コード **の名前は、UIの名前と完全に一致している必要があります。**&#x200B;変数が設定されていない場合、`getVariable`は`undefined`を返します。 アクションで適切なデフォルトを使用できるか、または設定が必要なので明確なエラーを返す必要があるかどうかを指定します。

>[!NOTE]
>
>変数は、アプリのアクションハンドラーでのみ使用できます。ウィジェットで自動的に使用できるのは&#x200B;**個ではなく**&#x200B;個です。

ハンドラーの変更の準備ができたら、それらをコミットしてアプリのハンドラーリポジトリにプッシュします。 次のデプロイメントでは、最新のプッシュコードを使用します。 ハンドラーの編集について詳しくは、[生成ハンドラーのカスタマイズ ](/help/guides/customize-handler.md)を参照してください。

#### ステップ 3：デプロイとテスト {#deploy-and-verify}

1. [Workspace ]**で選択した環境と同じ環境にアプリ ](/help/guides/deploy-your-app.md)をデプロイします。**[!UICONTROL 
2. `name`が`Ada`に設定されているサポートされているLLM プラットフォームからアクションを呼び出します。 [ChatGPT プラグインのテスト ](/help/guides/test-in-chatgpt.md)または[Claude コネクタのテスト ](/help/guides/test-in-claude.md)を参照してください。
3. 応答が`Good day, Ada!`であることを確認してください。 これにより、ハンドラーが設定された変数を読み取り、デフォルトの挨拶を上書きすることを確認します。

他の環境を設定するには、**[!UICONTROL Workspace]**&#x200B;で選択し、適切な値で設定を繰り返してからデプロイして、その環境で検証します。


>[!NOTE]
>
>ステージと実稼動には&#x200B;**独立した設定**&#x200B;があります。 一方の環境の変更は、もう一方の環境に影響を与えることはありません&#x200B;**1}。**&#x200B;必要に応じて、両方の環境で同じ名前を使用し、それぞれに適切な値を選択します。

>[!TIP]
>
>デプロイする前にローカルでテストするには、[ ローカルハンドラーの開発とテスト ](/help/reference/development.md)を参照し、変数をローカルサーバーに渡します。
>
>`node server/local.js --param 'LLMA_VARIABLE_NAMES=["GREETING_PREFIX"]' --param GREETING_PREFIX=Howdy`

### 変数の更新 {#update-or-delete}

1. 変数の行の編集コントロールを選択します。
2. 変数の&#x200B;**[!UICONTROL 現在の値]**&#x200B;を確認し、**[!UICONTROL 新しい値]**&#x200B;を入力します。

   ![Update GREETING_PREFIX – 値をGood dayからHowdy](/help/assets/guide-app-variables/update-variable-dialog.png)に変更します

3. 「**[!UICONTROL 更新]**」を選択します。
4. アプリを同じ環境に再びデプロイし、変更された動作を確認します。

更新は、値のみを変更します。 変数&#x200B;**は名前を変更できません**&#x200B;です。別の名前を使用するには、既存の変数を削除して新しい変数を追加してから、ハンドラーを更新して新しい名前を読み取ります。

### 変数の削除 {#delete-a-variable}

1. アクションに引き続き変数が必要かどうかを確認します。 必要に応じて、ハンドラー&#x200B;**first**&#x200B;を更新してプッシュします。
2. 変数の行の削除コントロールを選択します。 複数のエントリを削除するには、チェックボックスを選択し、**[!UICONTROL 削除]**&#x200B;を選択します。
3. 確認ダイアログで名前を確認し、**[!UICONTROL 削除]**&#x200B;を選択します。

   ![GREETING_PREFIXを削除 – パーマネント削除を確認](/help/assets/guide-app-variables/delete-variable-dialog.png)

4. アプリを同じ環境に再びデプロイします。

>[!IMPORTANT]
>
>削除&#x200B;**CANNOT**&#x200B;は元に戻せません。適切な変数を選択してください。 デプロイ済みアプリは、次のデプロイメントまで既存の設定を保持します。 このデプロイメントの後、ハンドラー&#x200B;**は削除された変数を受け取らなくなるため、必要なアクションで失敗する可能性があります。**

## ルールと制限 {#good-to-know}

| 項目 | ルール |
|------|------|
| 名前 | 最大64文字：大文字、数字、アンダースコア（数字で始まらない）。 **アプリと環境ごとに**&#x200B;は一意である必要があり、ハンドラーと一致する必要があります。 |
| 予約済みの名前 | `LLMA_`と`MCP_SERVER_URL`で始まる名前。 |
| 値 | **必須** （最大500文字）。 先頭と末尾のスペースは削除されます。 |
| 制限 | 50の変数を割り当てることができます。 |
| 視認性 | 変数の値は表示およびコピー可能です。 計画的なシークレットのサポートにより、保存された値は非表示のままになります。 |
| 変更点 | 選択した環境への次のデプロイメントに対して有効になります。 |

## トラブルシューティング {#verify-configuration}

| 表示される内容 | 実行内容 |
|--------------|------------|
| **[!UICONTROL Add]**&#x200B;は無効で、ページに&#x200B;**[!UICONTROL Workspaceの制限が]**&#x200B;に達していることが表示されます | 不要になった変数を削除します。 |
| *大文字、数字、アンダースコアのみを使用* | 名前を変更（例：`API_BASE_URL`）。 |
| *この名前はプラットフォームによって予約されています* | `LLMA_`で始まらず`MCP_SERVER_URL`ではない名前を選択してください。 |
| *この名前の変数は既に存在します* | 代わりに、既存の変数を更新してください。 |
| *この変数は別の場所で変更されました* | ページを更新して、もう一度試してください。 |
| *変数を読み込めませんでした* | ページをリロードします。 それでも解決しない場合は、アプリへのアクセス権があるかどうかを確認してください。 |
| アクションは新しい値を使用しません | 変数を保存した&#x200B;**後**&#x200B;に、テストした環境と同じ環境にデプロイされたこと、ハンドラーの変更がプッシュされたこと、名前が&#x200B;**正確に**&#x200B;と一致することを確認してください。 **[!UICONTROL 最終更新日]**&#x200B;は、値が保存された時点を示します。デプロイされた時点ではありません。 |
| `getVariable is not a function` | このアプリは1.1.0より古いランタイムを使用しています。 [開始する前に](#before-you-begin)の説明に従ってアップグレードしてから、デプロイします。 |
| 変数を削除すると、アクションが失敗します | 変数を再度追加するか、ハンドラーを更新して不要にしてデプロイします。 |
