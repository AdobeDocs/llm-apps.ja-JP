# アクションの作成 {#creating-actions}

>[!IMPORTANT]
>
>[!DNL Adobe LLM Apps]は現在Betaにいます。
>
>ここに示す機能、ワークフロー、UIは、必ずしも製品の最終状態を表すものではありません。 Betaに参加するには、llm-apps-beta@adobe.comに電子メールを送信します。

アクションとは、製品の検索、可用性の確認、サービスの予約など、LLM コミュニケーション内でアプリが提供する機能のことです。 各アクションのハンドラーがタスクを実行し、オプションのウィジェットが結果を表示します。

[&#x200B; インフラストラクチャのセットアップ &#x200B;](/help/guides/create-app.md)の後、アプリ ページからアクションを作成する方法を選択します。 Adobeのマネージドインフラストラクチャと独自のリポジトリの両方で、自動生成を利用できます。

**このガイドでは、** Web サイトからアクションを生成する方法と、自分でアクションを作成する方法について説明します。 自動生成の場合は、アプリをデプロイしてテストする前に、プロセスを開始し、結果を確認します。

## アクションの構築方法の選択

アプリを開きます。 Adobeがまだインフラストラクチャを準備している場合は、セットアップが完了するまで待ちます。

「**[!UICONTROL アクション]**」セクションの&#x200B;**[!UICONTROL アクションをどのように作成しますか？]** 2つの選択肢を提供：

| 選択肢 | 次の場合に使用 |
|---|---|
| **[!UICONTROL アクションを自動的に作成]** | プラットフォームでweb サイトを分析し、提案されたアクション、ハンドラーコード、テスト、ウィジェットを生成する必要があります。 これが推奨される出発点です。 |
| **[!UICONTROL 自分でアクションを作成します]** | 各アクションを定義し、その実装を自分で指定する必要があります。 |

アプリケーション作成ウィザードでインフラストラクチャを選択しても、これらのオプションは選択されません。

## web サイトからのアクションの生成 {#generate-from-website}

1. 「**[!UICONTROL アクションを自動的に作成]**」を選択します。
2. **[!UICONTROL Web サイト]**&#x200B;で、ブランドの製品、サービス、または顧客タスクを表すパブリック HTTPS web サイトを入力します。 この例では `https://frescopa.coffee/` を使用しています。
3. 「**[!UICONTROL 自分のアクションを作成]**」を選択します。

![&#x200B; アクション – 開始する前に公開web サイトを入力して自動生成を選択しました](/help/assets/guide-creating-actions/build-choice.png)

分析を許可されたweb サイトを使用します。 機密情報やアクセス制御情報を公開するサイトを提供しないでください。

「**[!UICONTROL 自分のアクションを作成する]**」を選択すると、生成が開始されます。URLを入力するだけでは開始されません。 アプリを再作成したり、インフラストラクチャウィザードを再度開いたりする必要はありません。

### 生成の進行状況を確認

アプリページには、**[!UICONTROL アクションが生成されています]**&#x200B;と表示されます。 「**[!UICONTROL アクションに移動]**」を選択するか、ナビゲーションから「**[!UICONTROL アクション]**」を開いて、進行状況を確認します。

UIは、生成に最大30分かかると見積もります。 ページを離れ、必要に応じて後で戻ります。

![&#x200B; アクション – 生成が実行中で、アクションページ &#x200B;](/help/assets/guide-creating-actions/generating.png)で進行状況を確認するためのリンクが表示されます

生成時に、プラットフォーム：

1. web サイトを分析し、アプリの顧客タスクを特定します。
2. 説明や入力パラメーターなど、提案されたアクションのメタデータを作成します。
3. サーバーサイドのハンドラーとテストをアクションリポジトリで生成します。
4. EDS リポジトリでウィジェットを生成します。
5. 生成されたアクションをレビュー用に準備します。

プラットフォームがweb サイトを分析している間、「**[!UICONTROL 会話エクスペリエンスのアクションを検出する]**」というアクション ページが表示されます。 提案されたアクションは、プラットフォームが検出したときに表示されます。コードとウィジェットのプレビューはまだ生成されている可能性があります。 各アクションを確認する前に、生成が終了するのを待ちます。

>[!IMPORTANT]
>
>生成されたハンドラーは、最初に代表的なサンプルデータを使用します。 web サイト分析では、アプリを本番API、ライブ在庫、決済サービス、予約システムに自動的に接続することはありません。

生成でエラーが報告された場合は、表示されるエラーを読み取り、[&#x200B; トラブルシューティングガイダンス &#x200B;](/help/reference/troubleshooting.md)を確認してください。 生成エラーをバイパスするだけのアクションを承認しないでください。

## 生成されたアクションの確認 {#review-generated-actions}

デプロイメントの前に、提案された各アクションを確認します。 これは便利なタスクであり、生成された動作がアプリの意図した動作と一致することを確認します。

![&#x200B; アクション – 生成されたFrescopa アクションはレビューの準備が整っており、デプロイされていません](/help/assets/guide-creating-actions/actions-ready-for-review.png)

1. **[!UICONTROL アクション]** ページで、準備が整っているアクションの&#x200B;**[!UICONTROL レビュー]**&#x200B;を選択します。
2. アクションの説明、入力パラメーター、注釈、表示、生成ハンドラーを確認します。
3. アクションにウィジェットがある場合は、ウィジェットの設定とプレビューを確認します。
4. 生成されたコードとテスト（リンクされたプルリクエストを含む）を確認します。 何がサンプルの動作であるか、何を実際の統合に置き換える必要があるかを確認してください。
5. アクションの準備ができたら、「**[!UICONTROL レビュー済みとしてマーク]**」を選択します。
6. アクションリストに戻り、残りのアクションについても繰り返します。

保存されたアクションエディターでは、**[!UICONTROL LLM ウィジェットの詳細]**、**[!UICONTROL アクションの詳細]**、および&#x200B;**[!UICONTROL Analytics]**&#x200B;が分離されます。 ウィジェットとハンドラーのプルリクエストをそれぞれのタブで確認します。

![生成されたアクション – 現在のエディターのタブとレビュー済みとしてマークします。リポジトリリンクは非表示です](/help/assets/guide-creating-actions/generated-action-review.png)

**[!UICONTROL レビュー済みとしてマーク]**&#x200B;を選択すると、結合ブロッカーが残っていない場合に、アクションで生成されたプルリクエストが結合されます。 開いているプルリクエストでレビューがブロックされた場合は、ブロッカーを解決して再試行します。 未解決のコード生成または結合エラーを含む実装を承認しないでください。

生成されたすべてのアクションを確認すると、「**[!UICONTROL すべてのアクションがレビューされました！]**」というアクション ページが表示されます。 アプリに戻るには、**[!UICONTROL アプリページに移動]**&#x200B;を選択します。

レビューはデプロイメントではありません。 アクションは、アプリをデプロイするまで、アプリのMCP サーバーを通じて使用できません。

## 自分でアクションを作成 {#manual-actions}

Web サイトからアクションを生成しない場合：

1. アプリページのアクション作成オプションで、**[!UICONTROL 自分でアクションを作成する]**&#x200B;を選択します。
2. 「**[!UICONTROL アクションを作成します]**」を選択します。
3. アクションページで、「**[!UICONTROL アクションを作成]**」を選択します。
4. 「[&#x200B; ゼロからアクションを作成](/help/guides/create-action.md)」に従って、メタデータを定義し、ハンドラーを実装し、必要に応じてウィジェットを接続します。

インフラは同じままです。 手動作成を選択しても、ハンドラーコードが作成されたり、ビジネスシステムが接続されたりすることはありません。

必要に応じて、自動生成されたアクションを確認した後、手動アクションを追加します。

## デプロイとテスト

生成された作業を確認した後：

1. [&#x200B; アプリを](/help/guides/deploy-your-app.md)から&#x200B;**[!UICONTROL ステージ]**&#x200B;にデプロイします。
2. ステージング MCP サーバーのURLを使用して、[ChatGPT](/help/guides/test-in-chatgpt.md)または[Claude](/help/guides/test-in-claude.md)でテストします。
3. 各アクションに一致するプロンプトと、そのアクションを呼び出さない無関係なプロンプトをテストします。 テキスト応答とウィジェットのインタラクションの両方を確認します。

このアプリを顧客が利用できるようにするには、[&#x200B; ハンドラーをカスタマイズ &#x200B;](/help/guides/customize-handler.md)してAPIを接続し、[&#x200B; ウィジェットをカスタマイズ &#x200B;](/help/guides/widgets.md)する必要があります。 ステージでアプリをテストして、アプリが期待どおりに動作することを確認します。 テストが成功した後にのみ実稼動環境にデプロイします。
