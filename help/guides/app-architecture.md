# アプリのワイヤリング方法 {#app-architecture}

>[!IMPORTANT]
>
>[!DNL Adobe LLM Apps]は現在Betaにいます。
>
>ここに示す機能、ワークフロー、UIは、必ずしも製品の最終状態を表すものではありません。 Betaに参加するには、llm-apps-beta@adobe.comに電子メールを送信します。

**LLM アプリ**&#x200B;を使用すると、ブランドのサービスをAI会話に取り込むことができます。 たとえば、顧客がコーヒーのレコメンデーションを尋ね、アプリが一致する商品を見つけ、アシスタントがその結果を表示します。

**このガイドでは、** アプリの各部分の機能、変更点、およびユーザーがアプリを使用する際の各部分の連携について説明します。

## アプリの3つの部分

1つのアプリは、*製品の参照*、*製品の比較*、*ストアの検索*&#x200B;など、複数の関連アクションをグループ化できます。 各アクションには、独自の設定、ハンドラー、オプションのウィジェットがあります。 アクションを追加するには、別のリポジトリのペアは必要ありません。

インタラクティブウィジェットを持つアプリには、アクション設定、ハンドラーコード、ウィジェットコードの3つの部分があります。 [!DNL LLM Apps]の設定を管理しています。 ハンドラーとウィジェットコードは、2つの別々の[!DNL GitHub] リポジトリにあります。

```text
┌───────────────────────┐   ┌───────────────────────┐   ┌───────────────────────┐
│ 1. LLM Apps UI        │   │ 2. Handler repository │   │ 3. Widget repository  │
│                       │   │                       │   │                       │
│ Action descriptions   │   │ Connects to your APIs │   │ Widget layout         │
│ Required information  │   │ Runs the task         │   │ Branding and styles   │
│ When to use an action │   │ Returns results       │   │ Interactive controls  │
└───────────────────────┘   └───────────────────────┘   └───────────────────────┘
            │                           │                           │
            └───────────────────────────┼───────────────────────────┘
                                        ▼
                    ┌───────────────────────────────────────┐
                    │ Your app in an AI conversation        │
                    │ The action runs and the widget        │
                    │ shows the result.                     │
                    └───────────────────────────────────────┘
```

- **アクション設定でタスクを説明します。** アクションを実行するタイミングと必要な情報をアシスタントに伝えます。 商品検索の場合、その情報はカテゴリーや検索語かもしれません。
- **ハンドラーが作業を行います。** システムからデータを取得したり、タスクを実行したりします。 たとえば、商品検索ハンドラーは、カタログから一致する商品を取得します。
- **ウィジェットに結果が表示されます。** 名前、価格、ボタンが付いた商品カードなど、顧客が閲覧したり操作したりするものを制御します。

各アクションにウィジェットを追加することをお勧めします。 ウィジェットを利用すれば、プレゼンテーションをAI アシスタントに任せるのではなく、結果の表示や顧客とのやり取りを制御できます。 テキストのみの応答もサポートされています。

## 変更の場所

| 変更する内容 | 編集する場所 |
|---|---|
| アシスタントがアクションを使用した場合、またはアクションが要求する情報 | [LLM アプリのアクション設定](/help/reference/reference-docs.md) |
| その結果がどこから来たのか、またはアクションが実行されたときにどうなるか | [&#x200B; ハンドラーリポジトリ内のハンドラーコード &#x200B;](/help/guides/customize-handler.md) |
| レイアウト、ブランディング、インタラクションなど、結果がどのように表示されるか | [&#x200B; ウィジェットリポジトリ内のウィジェットコード &#x200B;](/help/guides/widgets.md) |

3つの部分の一貫性を保つ： 例えば、ハンドラーが返す情報を変更した場合、新しい結果を表示するようにウィジェットを更新します。

## 会話の中で何が起こるか

デプロイメント後、アプリには&#x200B;**MCP サーバーURL**&#x200B;という接続URLがあります。 このURLをサポートされているAI プラットフォームに追加すると、アシスタントがアプリのアクションを検出して使用できるようになります。

商品検索アクションとウィジェットを含むアプリの場合：

1. お客様がアシスタントに尋ねます。*コーヒーポッドを見せてください。*
2. アシスタントはアクションの説明を使用して、商品検索アクションを選択します。
3. ハンドラーは、カタログから一致する製品を取得します。
4. ウィジェットには、会話の中で商品がカードとして表示されます。
5. 顧客は結果を確認するか、フォローアップで質問します。

顧客が会話を続ける間、アプリは情報やサービスを提供します。 ウィジェットのサポートは、LLM プラットフォームによって異なります。

## 変更を適用してテストする

更新されたエクスペリエンスをテストする前に、ウィジェットの変更を公開し、アクションの変更をデプロイします。 [&#x200B; アプリのデプロイ &#x200B;](/help/guides/deploy-your-app.md)に従って、サポートされているLLM プラットフォームでアプリをステージングおよびテストします。

自動生成アクションは、サンプルデータから始まります。 ハンドラーを実際のシステムに接続し、顧客が利用できるようにする前にアプリをテストします。
