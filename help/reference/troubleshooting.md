# トラブルシューティング {#troubleshooting}

>[!IMPORTANT]
>
>[!DNL Adobe LLM Apps]は現在Betaにいます。
>
>ここに示す機能、ワークフロー、UIは、必ずしも製品の最終状態を表すものではありません。 Betaに参加するには、llm-apps-beta@adobe.comに電子メールを送信します。

観察できる症状から始めます。 トラブルシューティング中は、資格情報、トークン、プライベート MCP URL、機密性の高いハンドラーの結果を共有しないでください。

## アプリ作成とアクション生成

| 症状 | 体験する施策 |
|---------|-------------|
| Adobe managed infrastructureの設定が失敗する | 「**セットアップに失敗しました**」のエラーを読み取り、**再試行**&#x200B;を選択します。 ページで進行状況を確認できない場合は、**もう一度確認**&#x200B;を選択します。設定はバックグラウンドで続行されます |
| AEM プログラムはありません | 管理者にプログラムへのアクセスを依頼します。 読み込みに失敗した場合は、**プログラムの読み込みを再試行**&#x200B;を選択します |
| 新しいリポジトリが表示されない | **別のリポジトリを接続**&#x200B;して、Adobe LLM Apps GitHub アプリにアクセス権を付与し、ウィザードに戻って、**組織とリポジトリを更新**&#x200B;を選択します |
| アクションまたはウィジェットリポジトリの検証が失敗する | 互換性のある既存のプロジェクトまたは空のリポジトリを使用します。 アクションとウィジェットに個別のリポジトリを使用してから、**リポジトリの検証**&#x200B;をもう一度選択します |
| AEM Code Syncが検出されない | ウィジェットリポジトリ用のAEM Code Syncをインストールし、確認ページでサイト管理者として自分自身を追加し、ウィザードに戻り、**AEM Code Sync インストールの検証**&#x200B;を選択します |
| アプリの作成でアクションが生成されませんでした | アプリ制作はインフラを整えるだけ。 アプリページで、**アクションを自動的に作成**&#x200B;を選択し、**Web サイト**&#x200B;と入力して、**アクションを作成**&#x200B;を選択します。 [ アクションの作成](/help/guides/creating-actions.md)を参照 |
| アクションは引き続き | UIは、生成に最大30分かかると見積もります。 「アクション」ページで進行状況を確認するか、ページを離れて後で戻ります |
| アクション生成レポートの失敗 | web サイトがHTTPSで公開されており、独自のリポジトリの場合、リポジトリアクセスが引き続き有効であることを確認します。 問題が引き続き発生する場合は、表示されるエラーメッセージをBeta チームに送信します |

## アクションとハンドラー

| 症状 | 体験する施策 |
|---------|-------------|
| アクションは呼び出されません | 会話でアプリのプラグインまたはコネクタを有効にします。 アクション設定の&#x200B;**AI モデルへの公開**&#x200B;を確認し、アプリ ページのアクションの&#x200B;**表示** スイッチがオンになっています。 説明を改善し、メタデータの変更を再展開する |
| 空またはエラーの応答 | `npm test`を実行してから、MCP インスペクターまたは`curl`でハンドラーを呼び出します。 [ ローカルハンドラーの開発とテスト ](/help/reference/development.md)を参照 |
| ハンドラーはローカルで動作しますが、デプロイメント後は動作しません | 最新のプッシュされたコミットを確認し、ランタイム設定を確認し、アクションコード識別子が`actions/<code-identifier>/index.js`と一致することを確認します |
| 生成されたアクションをレビュー済みとしてマークすることはできません | ハンドラーとウィジェットの生成が成功したことを確認します。 生成されたプル要求を確認して結合の競合を確認し、アクションを再読み込みして、**レビュー済みとしてマーク**&#x200B;をもう一度選択します |

## ウィジェット

| 症状 | 体験する施策 |
|---------|-------------|
| Widgetがレンダリングされない | スクリプト URL、ウィジェット URL、HTTPS、EDS パブリケーション、CSP ドメイン、およびCORS ヘッダーを確認します |
| ウィジェットはレンダリングされますが、データは表示されません | MCP Inspectorでハンドラーを呼び出し、`structuredContent`の形状を`bridge.toolResult`から読み取ったフィールドと比較します |
| Widgetは直接プレビューでは機能しますが、ChatGPTでは機能しません | 直接プレビューでは、サンプルデータを使用できます。 デプロイされたハンドラー結果をテストし、EDS オリジンがCORSおよびCSPで許可されていることを確認します |
| ブラウザーリクエストはブロックされています | 必要なオリジンのみを正しいCSP フィールドに追加し、再展開します |
| HTTP ヘッダーエディターは設定を保存できません | [AEM Configuration Service](https://aem.live/docs/config-service-setup)を使用するか、EDS管理者にサイトヘッダー設定の初期化を依頼します |

個人データや機密データを含めることができる完全な`bridge.toolResult`値は記録しないでください。

## デプロイメント

| 症状 | 体験する施策 |
|---------|-------------|
| **準備中**&#x200B;にデプロイメントが失敗しました | ハンドラーリポジトリがリンクされていて、Adobe Developer Console アクセスが有効であることを確認します |
| **ビルド アプリ**&#x200B;中にデプロイメントが失敗しました | `npm install`、`npm test`、`npm run build`をローカルで実行します。 依存関係、構文、またはテストの失敗を修正し、変更をプッシュします |
| デプロイメントは成功しましたが、変更がありません | 想定されたコミットがプッシュされ、同じ環境に再デプロイされたことを確認します |
| アクションは引き続き&#x200B;**デプロイされていません** | アクションを確認するか、そのメタデータを変更した後に、もう一度展開します |

## 認証 {#authentication}

**[!UICONTROL 認証を有効にする]**&#x200B;がオンの場合に適用されます。 [独自のID プロバイダーでエンドユーザーを認証する](/help/guides/authentication.md)を参照してください。

| 症状 | 体験する施策 |
|---------|-------------|
| 設定を保存した後もアクションは公開されたままです | その環境にアプリを再びデプロイします。 認証の変更は、次のデプロイで有効になります |
| 環境を切り替えると設定が正しく表示されない | **[!UICONTROL Workspace]** ピッカーに、意図した環境が表示されていることを確認します。 **[!UICONTROL ステージ]**&#x200B;と&#x200B;**[!UICONTROL 実稼動]**&#x200B;は個別に設定されています |
| ログインが開始されない | 認証を有効にした後にアプリをデプロイし、アクションで&#x200B;**[!UICONTROL 必須]**&#x200B;が使用されていることを確認します。 **[!UICONTROL オプション]** アクションは、ハンドラーがサインインを要求する場合にのみプロンプトが表示されます |
| プラットフォームが間違ったログインページにユーザーを送信する | **[!UICONTROL 発行者]**&#x200B;がID プロバイダーの発行者URLと完全に一致し、パブリック HTTPS経由で到達できることを確認します |
| ログインは成功しますが、すべての呼び出しは拒否されます | ID プロバイダーが、その環境のアプリのMCP サーバーURLをオーディエンスとするトークンを発行し、トークンが非対称アルゴリズムで署名されたJWTであることを確認します。 [ トークン要件](/help/reference/authentication-reference.md#token-requirements)を参照してください |
| ID プロバイダーはトラフィックを受信しません | プロバイダーの検出、認証、トークンのエンドポイントは、パブリック HTTPS経由で到達できる必要があります。 ファイアウォール、WAF、IP アドレスが手前にあることを確認します。プロバイダーが手元にない場合は、アプリにアクセスできます |
| ID プロバイダーは、要求されたオーディエンスに対するトークンの発行を拒否します | 一部のプロバイダーは、登録されているリソースに対してのみトークンを発行します。 アプリのMCP サーバーURLがID プロバイダーのリソース識別子として登録されていることを確認します |
| ログイン時に新しく追加されたスコープは要求されません | LLM プラットフォームは、アプリが公開したメタデータを数分キャッシュします。 待ってから、ログインを再試行してください |
| ユーザーは、スコープのために再度ログインするよう求められます | アクションには、トークンが実行しないスコープが必要です。 ID プロバイダーのクライアントの付与にスコープを追加するか、アクションから削除します |
| ユーザーにログインのプロンプトが繰り返し表示される | 発信者のIDを確認せずに、すべての呼び出しで`extra.challengeAuth()`を返すハンドラーは、認証後に再度サインインを要求します。 アクションに必要なIDがない場合にのみ認証を要求します |
| ユーザーがID プロバイダーに到達する前に、ログインが拒否されます | LLM プラットフォームが送信したリダイレクト URIが、認証サーバーに登録されていません。 一部のプラットフォームではコネクタごとに異なるコネクタが発行されるため、コネクタ設定画面に表示される値を登録します |
| サポートされていない範囲メッセージで保存がブロックされています | スコープを&#x200B;**[!UICONTROL サポート対象]**&#x200B;に追加するか、スコープを必要とするアクションから削除します |
| [!DNL Claude]でのログインを求める公開アクションがまだ表示されます | コネクタが、必要に応じて&#x200B;**[!UICONTROL サインインを使用することを確認します]**。現在&#x200B;**[!UICONTROL サインインしていません]**。 古いデプロイ済みアプリの場合は、ランタイムを更新して再デプロイします。 現在のランタイムで混在アプリケーションを使用すると、公開アクションを匿名で呼び出すことができます |
| **[!UICONTROL オプション]** アクションは、ログインテキストを返しますが、Claudeのログインプロンプトは返しません | `extra.challengeAuth()`はChatGPT ツール結果チャレンジです。 ポータブルサインインゲートの場合は、**[!UICONTROL Required]** アクションを使用して、ランタイムがClaudeが期待するHTTP チャレンジを返します |
| すべてのアクションが&#x200B;**[!UICONTROL None]**&#x200B;であるにもかかわらず、アプリはログインを求めるメッセージを表示します | **[!UICONTROL 認証を有効にする]**&#x200B;をオフにしてデプロイします。 オンになっている間、アクションがゲーテッド化されていない場合でも、アプリは認証サーバーをアドバタイズします |

アクセストークン、要求セット、またはID プロバイダーのクライアントシークレットをサポートリクエストに貼り付けないでください。

## ChatGPT プラグイン

| 症状 | 体験する施策 |
|---------|-------------|
| プラグインが表示されない | [chatgpt.com/plugins](https://chatgpt.com/plugins)を開き、アカウントまたはワークスペースでカスタム MCP サーバーが許可されていることを確認し、生成されたプラグインをインストールまたは接続します |
| プラグインの作成に失敗する | 完全なHTTPS MCP サーバーのURLを&#x200B;**アプリをテスト**&#x200B;から再度コピーし、アプリに一致する認証方法を選択します。 失敗したOAuthの回避策としてではなく、公開アプリにのみ&#x200B;**認証なし**&#x200B;を使用する |
| プラグインは接続しますが、アクションを呼び出すことができません | プラグインがチャットに添付され、アクションがモデルに公開され、最新バージョンがデプロイされていることを確認します |
| プラグインが間違った環境を使用しています | 目的のステージングまたは実稼動MCP サーバーのURLを使用して、プラグインを編集または再作成します |
| プラグインに古いアクションメタデータが表示される | 変更をデプロイし、ChatGPT接続で「**更新**」を選択してから、新しい会話を開始します |

問題が解決しない場合は、Beta チームに連絡する前に、アプリ名、環境、失敗した手順、時間、表示されるエラーメッセージを記録してください。 機密情報や機密性の高い顧客データは含めないでください。
